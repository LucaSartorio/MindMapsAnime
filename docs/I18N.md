# Traduzioni dei dataset (lingue con URL propri oltre a IT/EN)

AniMapVerse scrive i dataset in **italiano e inglese** (le lingue sorgente,
`SOURCE_LOCALES`). Le altre lingue dell'interfaccia (ja, fr, de, es) traducono
la UI e ricadono sull'inglese per i contenuti. Una lingua riceve **URL propri**
(`/es/...`, `/fr/...`) solo quando i contenuti sono davvero tradotti: questa guida spiega
come. Lingue pubblicate: **spagnolo** (tutti gli 8 mondi) e **francese** (mondo per mondo,
vedi `translatedLocales`).

## Architettura

| Pezzo | Dove | Cosa fa |
| --- | --- | --- |
| Lingue URL | `SEO_LOCALES` in `src/seo/config.ts` | `it`, `en`, `es`, `fr`. Home e pagine informative esistono in tutte. |
| Mondo pubblicato in una lingua | `AnimeWorld.translatedLocales` in `src/data/worlds.ts` | Solo questi mondi hanno `/es/<mondo>/...` o `/fr/<mondo>/...`. Per gli altri `worldPath('fr', w)` ricade su `/en` (`seoLocaleFor`). |
| Overlay di traduzione | `src/data/<slug>/i18n/<lingua>.ts` | Mappa `chiave → testo`, chunk lazy separato dal dataset. |
| Impronte del sorgente | `src/data/<slug>/i18n/<lingua>.meta.json` | Hash del testo inglese tradotto: rileva le traduzioni obsolete. |
| Registro | `worldTranslationLoaders` in `src/data/registry.ts` | `ensureWorldTranslation(slug, locale)` applica l'overlay al dataset (in place, idempotente). |
| Motore | `src/data/shared/translations.ts` | Chiavi, applicazione, `isFullyTranslated`. |

**Chiavi.** Percorso del `Localizable` dalla radice del dataset; gli elementi di
array con `id` sono indirizzati per id (stabili anche se l'ordine cambia):

```
characters[char-naruto].shortDescription
routes[route-naruto-journey].steps[3].description
factions[clan-uchiha].name        ← nome semplice: crea localizedName { it, en, es }
characters[char-krillin].name     ← anche i personaggi (i doppiaggi rinominano)
characters[char-kakashi].aliases[0]
characters[char-naruto].rank
characters[char-itachi].kekkeiGenkai[0]
factions[clan-hyuga].structure[0].members[2].label
```

**Tutto ciò che si vede è traducibile.** Oltre ai `Localizable`, sono voci
traducibili anche le STRINGHE semplici nei campi "nome" (`PLAIN_NAME_PATHS` in
`translations.ts`: alias ed epiteti, gradi descrittivi, kekkei genkai, etichette
di membri/titolari/partecipanti senza scheda, `localizedName` semplici). Una
stringa vale per tutte le lingue finché una lingua non le dà la sua forma; la
chiave è la stessa che avrebbe come `{ it, en }`.

**Nomi nelle lingue sorgente: `src/data/<mondo>/names.ts`.** I nomi it/en che
differiscono dal `name` dei dati (o lo correggono) stanno in un file per mondo,
con le stesse chiavi degli overlay: `"characters[char-dbz-krillin].name": { it:
"Crilin", en: "Krillin" }`. `withSourceNames` (applicato nell'`index.ts` del
mondo) crea i `localizedName`/oggetti derivati senza cambiare le chiavi, così
lo spagnolo e le lingue future restano allineati. Regola: il nome della
localizzazione UFFICIALE di quella lingua (doppiaggio/edizione); l'originale
dove la localizzazione lo mantiene (Rasengan, Bankai); le parti descrittive
(titoli, ordinali, epiteti, "Clan", "Pirati", gradi) sempre tradotte.

Il ramo `world` è incluso (es. `world.config.ability.categories[x].label`):
le etichette del `WorldConfig` passano dall'overlay, ma un valore `es` già scritto
in linea in `worlds.ts` (titolo, descrizione: servono anche alla home) vince
sull'overlay. Esclusi: `seoSlugs` e i cammini derivati dagli eventi (testi
generati da `localizeCharacterJourneys` con i template per lingua in
`src/data/shared/autoJourneys.ts`). I `localizedName` creati da una chiave
`.name` sono marcati come derivati, quindi riapplicare un overlay (o applicarne
uno di un'altra lingua) li aggiorna invece di trattarli come scritti a mano.

**Caricamento.** Pre-rendering e script applicano tutti gli overlay
(`loadWorldDatasetWithTranslations`). Sul client `preloadRoute(pathname, locale)`
li applica prima dell'idratazione; `WorldRoute` li carica quando la lingua
cambia durante la navigazione. Chi naviga in it/en non scarica nulla.

**Indicizzazione.** Una pagina entità `/es` è indicizzabile solo se **ogni**
testo dell'entità è tradotto (`isTranslatedIn` → `isFullyTranslated`). Un'entità
aggiunta ai dati senza traduzione resta quindi `noindex` in `/es` (con fallback
inglese) finché l'overlay non la copre: nessuna build rotta. La soglia di
contenuto minimo (`thin_content`) si misura sul testo sorgente, non sulla
traduzione. hreflang e sitemap includono `/es` solo dove la pagina esiste ed è
indicizzabile.

## Flusso di lavoro

```bash
npm run i18n:audit                                    # BLOCCANTE: etichette + voci mancanti nelle lingue pubblicate
npm run i18n:audit -- --locale fr                     # cosa manca per una lingua futura (report)
npm run i18n:audit -- --names                         # + nomi identici in tutte le lingue (revisione)
npm run i18n:status                                   # copertura per mondo: mancanti, obsoleti, orfani
npm run i18n:extract -- --world naruto --locale es --out tmp/naruto-es-todo.json
#   → { "<chiave>": { "en": "…", "it": "…" } }   (solo mancanti + obsoleti)
#   traduci in { "<chiave>": "testo" }  (opzioni: --kinds characters,events  --limit 200)
npm run i18n:merge -- --world naruto --locale es --from tmp/naruto-es.json
#   → riscrive src/data/naruto/i18n/es.ts (ordine del dataset) + es.meta.json
```

`i18n:merge` rifiuta chiavi inesistenti e testi vuoti e segnala testi identici
all'inglese o di lunghezza sospetta. Le correzioni a mano dell'overlay sono
ammesse: il merge successivo le conserva.

**Etichette derivate dai dati** (tipi di tecnica, attributi, gradi, ruoli, razze,
tipi di luogo e di fazione, trasformazioni, classificazioni, sigilli, tag mostrati):
config del mondo (`WorldConfig`) o mappe note esportate in
`src/utils/localization.ts` (`*_LABELS`) e `src/lib/tagLabels.ts` (`TAG_LABELS`;
un nome proprio è una stringa unica, voluta uguale ovunque). `i18n:audit`
fallisce se un id usato da un mondo non ha l'etichetta ESATTA in una lingua
pubblicata (niente `humanizeId`, niente catena di fallback).

**Pubblicare un mondo in una lingua**: overlay al 100% (`i18n:status`) →
registrare il loader in `worldTranslationLoaders` → aggiungere la lingua a
`translatedLocales` del mondo → `npm run build` (`test:seo`, `seo:check`: niente
description inglesi in `/es`) e `npm run smoke`.

**Quando cambia un testo inglese**: `i18n:status` lo segnala come *obsoleto*;
`i18n:extract` lo ripropone, `i18n:merge` aggiorna la traduzione e l'impronta.

Sharingan, Rasengan, Akatsuki, Konohagakure, nomi dei personaggi). Traduzioni

## Aggiungere un'altra lingua con URL (es. de)

È la procedura seguita per il francese.

1. `SEO_LOCALES` + `SEO_LOCALE_META` (`src/seo/config.ts`) e `SEO_STRINGS`
   (`src/seo/strings.ts`, TypeScript segnala ciò che manca).
2. Regola `accept-language` per `/` in `vercel.json`.
3. Template dei cammini derivati in `JOURNEY_TEXT` (`autoJourneys.ts`).
4. `npm run i18n:audit -- --locale de`: elenca TUTTO ciò che manca (etichette nelle
   mappe `*_LABELS`/`TAG_LABELS`/config dei mondi, voci del dataset). Completale.
5. Overlay per mondo + `translatedLocales`, come sopra: l'overlay copre anche
   nomi, alias, gradi ed etichette, quindi nulla resta indietro.
6. Il controllo "description nella lingua sbagliata" di `scripts/seo-check.ts`
   va esteso con un'euristica per la nuova lingua.
