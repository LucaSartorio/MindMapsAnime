# Social Analytics Contract

> The contract between the **Analyst Agent** (ChatGPT Work + the Metricool plugin, external) and the
> AniMapVerse repository. The agent READS metrics in Metricool and reports them as **analytics
> snapshots**; the repository validates them, keeps the latest metrics per post
> (`tools/social-engine/analytics/metrics.json`), scores performance (`catalog/performance.json`) and
> re-plans the next video (`catalog/next.json`).
> Machine-readable twin: [`tools/social-engine/analytics/schemas/analytics-snapshot.schema.json`](../tools/social-engine/analytics/schemas/analytics-snapshot.schema.json)
> (generated by `npm run social:schema`). Engine side: [`docs/SOCIAL_ENGINE.md` › Growth Engine](SOCIAL_ENGINE.md#growth-engine).

## 0. Roles

| Agent | Does |
| --- | --- |
| Content Agent | queues `catalog/next.json` → video rendered ([contract](SOCIAL_AGENT_CONTRACT.md)) |
| Publishing Agent | schedules/publishes via Metricool → publication receipts ([contract](SOCIAL_PUBLISHING_CONTRACT.md)) |
| **Analyst Agent** | reads Metricool analytics of PUBLISHED posts → **analytics snapshots** (this document) |

The repository never calls Metricool: no token, no API, no account id. The Publisher keeps working
when no analytics exist (cold start: variety first).

## 1. The agent's job

1. read `tools/social-engine/history/history.json`: every record with a platform entry
   `status: "published"` (its `providerPostUuid` / `providerPostId` / `publicUrl` identify the post);
2. in Metricool, read that post's metrics — **only the metrics of that network listed below**;
3. write ONE snapshot per render × platform in `tools/social-engine/analytics/pending/`
   (`[A-Za-z0-9][A-Za-z0-9._-]*.json`, ≤ 16 KB), e.g.
   `20261006T080000Z-dragonball_goku_character-journey_part-01_en-instagram-metrics.json`;
4. branch → PR with **only** new files in `analytics/pending/` (and/or `publication/pending/`) →
   *Social publication validate* green → merge → *Social publication state* applies it.

Suggested cadence: 24 h, 48 h and 7 days after publication (metrics arrive with delays; posts
younger than 48 h weigh less in the score). Re-sending newer values is the normal way to update.

## 2. Snapshot

```json
{
  "snapshotVersion": 1,
  "renderId": "character-journey:dragonball:goku:part-01@en",
  "platform": "instagram",
  "provider": "metricool",
  "collectedAt": "2026-10-06T08:00:00Z",
  "providerPostUuid": "-2035779932044177791",
  "metrics": { "views": 12450, "reach": 9800, "likes": 830, "comments": 41, "shares": 66, "saves": 120, "averageWatchTime": 14.2, "retention": null, "followersGained": 18 },
  "recordedBy": "chatgpt-work-analyst-agent"
}
```

| platform | metrics (number ≥ 0, or `null` = not provided / not available yet) |
| --- | --- |
| instagram | views · reach · likes · comments · shares · saves · interactions · averageWatchTime (s) · retention (0–1) · viewRate (0–1) · followersGained |
| tiktok | views · reach · likes · comments · shares · averageWatchTime (s) · fullVideoWatchedRate (0–1) · profileViews · followersGained |
| youtube | views · likes · comments · shares · watchMinutes · averageViewDuration (s) · subscribersGained |
| facebook | views · reach · likes · comments · shares · interactions |

- **missing** key = not reported this time → the previous value is kept;
- **`null`** = the network doesn't provide it / not available (never write `0` for "unknown");
- rates are fractions (`0.42`, not `42`); timestamps ISO 8601 with seconds and offset;
- unknown fields or metrics, negative numbers, duplicate JSON keys → rejected.

## 3. What the repository accepts

- the `renderId` exists and the post is **published** on that platform (scheduled → rejected);
- `providerPostUuid`, when given, is the published post's UUID;
- a snapshot older than the stored one is a no-op; the same snapshot twice is a no-op;
- one invalid snapshot → **none** of the batch is applied (invalid ones → `analytics/failed/` +
  `.error.json`, valid ones stay pending for the next run).

## 4. What it is used for

`catalog/performance.json`: per post, normalized rates (shares / views, comments / views,
likes / views, saves / views, follows / views, retention) → a 0–100 score with the configured
weights (retention 35 %, shares 20 %, comments 15 %, follows 15 %, saves 10 %, likes 5 %); per
content, anime, character, format, hook type, duration bucket and platform: mean + a shrunk estimate.
Facebook metrics are stored but never drive the plan. **Performance optimizes the editorial plan; it
never overrides the rotation rules.**

## 5. Never

Edit `metrics.json`, `performance.json`, `next.json`, history or the audit folders; invent metrics;
write `0` for a metric you couldn't read; put tokens, account names or raw API responses anywhere.
