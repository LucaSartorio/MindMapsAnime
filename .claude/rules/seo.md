# SEO — constraints (any page, URL, metadata or indexing change)

How it works: `docs/ARCHITECTURE.md` › SEO; full guide `docs/SEO.md`. Every public page is pre-rendered (SSG) with its
own metadata; the SEO layer (`src/seo/`) is data-driven: never hand-write SEO for one world/entity/page.

- **URLs** only from the path helpers (`worldPath`, `mapPath`, `categoryPath`, `entityPath`, `refPath` + `useSeoLang()`):
  `/{lang}/{world}/{category}/{slug}`, `lang ∈ it|en|es|fr`, English segments, lowercase, no trailing slash, no query.
  A world exists in `/es` or `/fr` only if listed in `translatedLocales` with an overlay (otherwise `/en`); ja/de are
  UI-only. Never concatenate `/worlds/...` or use `world.slug` in a URL.
- **Slugs are permanent and language-independent**: precedence `entity.slug` → published lock `src/data/<world>/slugs.ts`
  (generated by `npm run seo:slugs`, never hand-edited) → derived from the English name. To move a URL on purpose set
  `slug: 'new'` and run `seo:slugs` (old slug → permanent redirect, no chains). Retired slugs stay reserved. After
  adding entities run `seo:slugs` + `i18n:index` and commit both files.
- **IT/EN text is mandatory**: a plain-string `Localizable` counts as Italian → the `/en` page is `noindex`.
  `noindexReason()` explains every exclusion (`legal_page`, `coming_soon`, `thin_content`, `not_translated`).
- **Existence = `resolveSeoPath`** (router, pre-renderer, sitemap): unknown paths render `NotFoundPage` (real 404),
  never a `<Navigate>` (soft-404).
- **Metadata only from `buildPageMeta`** (`src/seo/strings.ts`), applied by `<Seo>` and `renderHeadHtml`; never add
  `<title>`/meta/canonical elsewhere. The post-hydration tab title (`buildTabTitle`) is short per section and `null`
  on entity pages and 404.
- **Index/noindex** (`isIndexable`, `src/seo/quality.ts`): content threshold AND text truly in that language. Never lower
  thresholds to index thin pages. hreflang only between indexable versions (reciprocal); noindex pages are not in
  the sitemap. Legal pages, coming-soon worlds, 404 and query URLs are noindex.
- **Canonical to another resource** only for projections (today: derived journeys → their protagonist's page): keep
  `index, follow`, exclude from sitemap + hreflang, never combine with noindex.
- **One intent per hub page** (landing / `/map` / arcs index, data-derived templates, never per-world copy); `MapGuide`
  stays rendered after hydration (the only text/link context of `/map`).
- **Internal links** are real `<a href>` (`CardLink`, `RefLinks`/`refPath`); every page renders `Breadcrumbs`.
- **Structured data** only WebSite/Organization/WebPage/CollectionPage/AboutPage/BreadcrumbList + `about`; never invent
  ratings, dates, authors or ownership. Sitemaps carry no `lastmod` without a per-URL source.
- **SSR-safety**: identical server/first-client render; route chunks via `lazyWithPreload` in `src/routes/lazyPages.tsx`;
  one `<h1>` per page. Technical routes (`/og/*`, `/share/*`, `/social/*`, `/render/*`) are never indexable.

**Checklist for every new feature / entity type / page**: URL · metadata IT/EN · canonical · hreflang · sitemap ·
internal links + breadcrumbs · structured data (only if truthful) · index/noindex · SSR-safety of the first render.
Checks: `npm run test:seo` → `npm run build` (prerender + `seo:check`, blocking), or `npm run smoke` instead of
`build` for UI changes (smoke runs the same build first).
