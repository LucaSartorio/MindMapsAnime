# i18n & `Localizable` — constraints

How it works: `docs/ARCHITECTURE.md` › i18n; full guide `docs/I18N.md` (workflow, glossaries).

- **Six UI languages** (`SUPPORTED_LOCALES`): `it` (reference) · `en` bundled (URL/source languages); `ja/fr/de/es`
  lazy (`LAZY_RESOURCES`). Fallback `ja|fr|de|es → en → it`. The URL language decides the content language.
- **UI keys identical in all six `src/i18n/resources/*.ts`** (`validate:i18n` diffs against `it`, blocking). Never
  hardcode a user-facing string, `aria-label` included.
- **Data text** is `Localizable` (`it`/`en` required) and is always rendered through `getLocalizedText` /
  `getEntityDisplayName` — never a `Localizable` object in JSX. New `Localizable` fields go into `LOCALIZABLE_FIELDS`.
  `localizedName` only when dubs differ; official it/en name variants in `names.ts`; `japaneseName` is used for `ja`.
- **Never translated**: ids, slugs, keys, tag values. Tags that are SHOWN (nations, boundaries, worlds) need a
  `TAG_LABELS` entry (`i18n:audit` checks it); proper nouns stay plain strings there.
- **es/fr dataset text only via overlays** `src/data/<slug>/i18n/<locale>.ts`: `npm run i18n:extract -- --world <w>
  --locale <l> --out tmp/<file>.json` → translate → `npm run i18n:merge -- --world <w> --locale <l> --from tmp/<file>.json`
  → `npm run i18n:index` (commit `translationIndex.ts`; `test:seo` fails when stale). Never add `es`/`fr` inside dataset
  files; `.meta.json` fingerprints are generated. An `/es` or `/fr` entity page is indexable only when ALL its text is
  translated (read from the generated index, never from runtime overlays). Publishing a world in a language = 100 %
  overlay + loader in `worldTranslationLoaders` + locale in `translatedLocales` + `i18n:index`.
- **Adding a UI language**: `SUPPORTED_LOCALES` + `LOCALE_META`/`LOCALE_FALLBACKS`, resource file, `LAZY_RESOURCES`,
  `UI_RESOURCES` (`validateI18n.ts`), flag + `LOCALE_FLAG`/`LOCALE_LABEL_KEY`, `languageSwitcher.<lang>` key everywhere,
  `ErrorBoundary` `STRINGS`. A UI-only language gets no URLs; URLs need datasets in that language (docs/SEO.md).

Checks: `npm run validate:i18n` · `npm run i18n:audit` (`-- --locale de` = what a new language needs) ·
`npm run i18n:status` · `npm run test:seo`.
